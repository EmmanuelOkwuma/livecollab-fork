## OPEN ITEM #1 — onMemberJoined HANDLER IS EMPTY (HIGHEST PRIORITY)
Root cause of guest Explorer being empty on initial join, CONFIRMED:

  grep -n "onMemberJoined" livecollabFolderContribution.ts
  219: this._register(livecollabService.onMemberJoined(async () => {
  }));

The handler is registered but completely empty. When a new member joins,
onMemberJoined fires on the host, the empty handler runs, nothing gets
broadcast, the guest Explorer stays empty. The tree only arrives later
because reconnects trigger a DIFFERENT broadcast path that has actual code.

THE FIX: add the file tree broadcast call inside the onMemberJoined handler,
same pattern as the reconnect broadcast that already works. Find the reconnect
broadcast in livecollabFolderContribution.ts and copy that pattern into the
empty handler body.

Two theories were ruled out before finding this:
1. Socket.io join race (socket not in room when broadcast fires) — WRONG.
   socket.join(roomId) at line 795 runs before room:member:joined at line 918.
2. Ordering issue on host side — never tested because empty handler found first.

## OPEN ITEM #2 — PERSISTENT SOCKET RECONNECT LOOP
Confirmed by direct count in MacBook workbench log:

  23 `socket connected` events
All in ONE session, clustered tightly.

Every reconnect runs: socket connected -> checking folder ->
_attachFolderToRoom() -> full 19-item tree re-broadcast.

This is persistent and long-standing, NOT caused by laptop sleep/wake.
Two separate sleep/relaunch explanations were proposed and BOTH were wrong.

NEXT STEP: trace WHY socket drops. Check server Socket.io ping/timeout
config, client reconnection settings, and whether 60-second Clerk token
lifetime + auth middleware is forcing disconnects. Also: re-broadcasting
the whole tree on every reconnect is wasteful — debounce or skip when tree
is unchanged.

## BUILD GOTCHAS (hard-won)
- minify-vscode uses STALE out-vscode/out-vscode-min cache. ALWAYS rm -rf
  both before packaging or fixes silently never reach the app.
- Minification renames locals and strips comments. Verify fixes with a
  unique console.log STRING, never a variable name or comment.
- Native modules are SHARED between arch builds. Building for one arch
  breaks the other until rebuilt back.
- product.json is copied not compiled — config-only changes skip recompile.
- TWO package.json files: repo root AND server/. Docker uses server/.
  Installing a server dep at root causes "Cannot find module" on Railway.
