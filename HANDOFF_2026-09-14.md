## OPEN ITEM #1 — PERSISTENT SOCKET RECONNECT LOOP (HIGHEST PRIORITY)
CONFIRMED by direct count in the MacBook workbench log:
  - 22 `reconnected — re-joining room` events
  - 24 `file tree broadcast: 19 items` events
  - 23 `socket connected` events
All in ONE session, clustered tightly (some ~9 log lines apart).

Every reconnect runs: `socket connected — checking folder` ->
`_attachFolderToRoom()` -> full 19-item tree re-broadcast.

User confirms this reconnect pattern has appeared in PAST session logs too,
i.e. it is persistent and long-standing, NOT caused by laptop sleep/wake.
(Two separate sleep/relaunch explanations were proposed during the session
and BOTH were wrong — do not assume a cause here without evidence.)

This is the most likely underlying cause of much of the session's
unpredictability: trees arriving at random times, the guest Explorer
populating or not depending on when it was observed, and the Explorer
appearing to "self-heal" twice while unattended.

NEXT STEP: trace WHY the socket drops. Check the server's Socket.io
ping/timeout config, the client's reconnection settings, and whether the
60-second Clerk token lifetime + auth middleware is forcing disconnects.
Separately: re-broadcasting the whole tree on every reconnect is wasteful
and should likely be debounced or skipped when the tree is unchanged.

## DELIBERATE SHORTCUTS (also in PRELAUNCH_ROADMAP.md #26)
1. **Folder flattening** — each host top-level directory becomes its own
   workspace root on the guest; the real parent folder name is NOT shown.
   Correct architecture (as VS Code Live Share does): add the ONE real
   parent folder as the single root with children nested. Display-only,
   no data loss. Guest "Remove folder from workspace" removes one entry only.
2. **No late-joiner Yjs history replay** — a new server-side Y.Doc is seeded
   once from current real content; prior edit history is not replayed.

## BUILD GOTCHAS (hard-won)
- `minify-vscode` uses a STALE `out-vscode`/`out-vscode-min` cache. ALWAYS
  `rm -rf` both before packaging or fixes silently never reach the app.
- Minification renames locals and strips comments — verify fixes with a
  unique console.log STRING, never a variable name or comment.
- Native modules (policy-watcher etc.) are SHARED between arch builds.
  Building for one arch breaks the other until rebuilt.
- product.json is copied, not compiled — config-only changes skip the
  full recompile.
- TWO package.json files: repo root AND server/. Docker uses server/.
  Installing a server dep at root causes "Cannot find module" on deploy.
